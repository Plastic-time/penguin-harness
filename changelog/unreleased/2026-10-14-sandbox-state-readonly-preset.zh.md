# 新增把 Agent 自身状态保持只读的沙盒预设

- **Date:** 2026-10-14
- **Type:** feature
- **Scope:** `core`, `server`, `web`, `plugins`, `docs`

[English](2026-10-14-sandbox-state-readonly-preset.md)

进入沙盒的会话可以写自己的工作区，但会话里跑起来的任何命令，同时也一直能写 Agent 自己的文件：它的记忆、指示文件、技能与定时任务。新的内置预设**工作区可写·状态只读**补上了这一块：工作区照常可写、网络照常开放，但 Agent 的整个 per-agent 根对会话的命令、钩子与 stdio MCP Server 保持只读——仍然可读，因此它配置的那个 Agent 依旧可以被查看，但不可写。会话的 scratchpad 是这个根更深的子目录，保持可写，计划、目标与附件的读写不受影响。

## 细节

- 沙盒词汇新增第四个策略值 `stateReadonly` 与新维度 `readonly-roots`：未声明该维度的后端不会被路由到这样的策略，而没有已挂载后端能实施时策略拒绝执行——与每个维度一样 fail-closed。忽略一个只读根等于放宽沙盒，正是接口禁止的那个方向，所以它作为维度声明，而不从模式推导。
- 只读根是 Agent 的整个 per-agent 根，由持有状态布局的 core 在每个围堵接口处点名。沙盒绝不创建它：盘上缺失的根会让 spawn 拒绝执行，而不是先把目录建出来、再声称自己把它保持只读。
- 设置卡的预设表新增「State read-only／状态只读」列，新内置预设与其余预设一样固定并可选。在用的后端都实施不了该维度时，这一列按既有限制的不可用面显示。服务端默认把状态保持只读时，只有管理员能放开某个会话的状态写入；会话的权限拣选与模式、网络一样携带这个值。
- bubblewrap 后端把全部路径挂载——临时区的 tmpfs、可写根、只读根——放进同一个顺序：路径更深者后挂载，同深度时只读在可写之后。正是这一个顺序让只读根无论部署把它放在哪里都成立：落进工作区内（或临时区内）的状态根在覆盖它的可写 bind 之后挂载并遮蔽它，而状态根内的 scratchpad 更深、再往后挂载，保持可写。masks 仍然最后挂载。
- WSL 后端在发行版内采用同一顺序，并把状态根翻译成它在发行版内的路径。在发行版内没有对应路径的只读根（另一个发行版的文件、网络共享）是错误而不是跳过：丢弃它等于放宽沙盒。
- sandbox-dsh 后端把它的 Landlock 踝扩展为可服务该维度：Landlock 是允许清单，只读根不需要新规则——没有任何授予在那里给出写权限；同一踝现在还把策略的可写根拼进启动器自己的授予旗标，因此 Landlock 下会话的 scratchpad 变为可写（此前这是该踝披露的限制）。落在某个可写授予之内的只读根无法表达——Landlock 没有做减法的规则——因此拒绝 spawn，而不是谎称成立。其余踝（bubblewrap、Seatbelt、Windows ACL runner）仍然只限制文件写入，不参与新维度的路由。
