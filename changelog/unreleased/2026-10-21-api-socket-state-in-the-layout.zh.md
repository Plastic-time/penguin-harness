# API socket 的重连与放弃，在布局里安静地说出来

- **Date:** 2026-10-21
- **Type:** fix
- **Scope:** `web`
- **PR:** [#1275](https://github.com/Prism-Shadow/penguin-harness/pull/1275)

[English](2026-10-21-api-socket-state-in-the-layout.md)

页面唯一的一条 API socket 驮着一个标签页里所有「活」的东西——本服务端的事件、机器聚合流、每一个打开的对话——而它连续失败时，页面一个字也不说：调用悄悄退回 fetch，流停在那里等，标签页看上去一切正常，实际上什么也不再跟随。连续三次握手没开起来之后就此作罢，仍然没有一句话。

socket 的处境现在是一个正式读数——`ApiSocket` 上的 `health()` 与 `onHealth()`，纯增量，重试与退避行为分毫未动——app 布局把曾经是沉默的那两态说成浮在任何页面顶上的一枚小药丸：

- **重连中**——一条断掉的 socket（或一个握手已开始失败的页面）正在被带回：中性的药丸带着转圈，「连接已断开，正在重连…」。自己愈合的抖动在消失前不曾挪动它打断的那一页的一行排版。
- **已放弃**——对着一个一直答着 `/api/me` 的服务端，第三次握手仍然没开：药丸转成警示色，「实时更新已断开」，旁边是这个处境唯一剩下的动作——重新加载——因为调用仍走 HTTP 可用，而流等的正是这一次刷新。

页面的首次连接不说任何话：还没有什么被丢掉，一次正常加载不该闪。文案跟随界面语言；放弃那一行是 `alert`，重连进行中只是 `status`。
